# Регламент профилирования памяти в Rust (rust-memory-profiling)

Данный навык устанавливает порядок анализа аллокаций кучи, выявления утечек памяти и оптимизации аллокаторов в приложениях на Rust.

## Ключевые требования

1. Никогда не включать профилировщик аллокаций в финальный релизный бинарный файл без флага сборки.
2. Использовать профилирование кучи через `dhat` под отдельным Cargo feature-флагом.
3. Проводить замеры на реалистичном объеме данных перед оптимизацией типов и структур.
4. Для системных утилит заменять стандартный аллокатор Windows на `mimalloc` для устранения фрагментации.

---

## Настройка зависимостей `Cargo.toml`

```toml
[dependencies]
mimalloc = { version = "0.1", default-features = false }

[dependencies.dhat]
version = "0.3"
optional = true

[features]
default = []
dhat-heap = ["dep:dhat"]

[profile.release]
debug = 1
```

---

## Интеграция `dhat` для сбора профиля кучи

В корневом файле `src/main.rs`:

```rust
#[cfg(feature = "dhat-heap")]
#[global_allocator]
static ALLOC: dhat::Alloc = dhat::Alloc;

#[cfg(not(feature = "dhat-heap"))]
#[global_allocator]
static GLOBAL: mimalloc::MiMalloc = mimalloc::MiMalloc;

fn main() {
    #[cfg(feature = "dhat-heap")]
    let _profiler = dhat::Profiler::new_heap();

    run_app();
}

fn run_app() {
    let mut data: Vec<String> = Vec::new();
    for i in 0..100_000 {
        data.push(format!("item_{}", i));
    }
}
```

## Сбор и анализ метрик

### Шаг 1. Запуск сценария под нагрузкой

```powershell
cargo run --release --features dhat-heap
```

По завершении выполнения программа создаст файл `dhat-heap.json` в корневой директории проекта.

### Шаг 2. Просмотр отчета

Для детального визуального анализа используется просмотрщик dhat:

```powershell
Start-Process "https://nnethercote.github.io/dh_view/dh_view.html"
```

В интерфейсе загружается сформированный `dhat-heap.json` для просмотра:
- Пикового потребления кучи (peak memory).
- Точек кода с наибольшим числом кратковременных аллокаций (churn).
- Мест с не освобожденной памятью перед выходом (утечки).

---

## Паттерны устранения избыточных аллокаций

1. Замена динамических строк `String` на срезы `&str` или `Cow<'a, str>`.
2. Предварительное выделение емкости для коллекций: `Vec::with_capacity(expected_len)`.
3. Использование структур `SmallVec` или `ArrayVec` для хранения небольшого фиксированного числа элементов на стеке.
4. Повторное использование буферов в цикле обработки вместо повторного выделения памяти на каждой итерации.

---

## Чек-лист проверки

- Запуск `cargo test` проходит успешно как с включенным флагом `dhat-heap`, так и без него.
- В кодовой базе отсутствуют комментарии.
- В релизной конфигурации по умолчанию сборка выполняется с высокопроизводительным аллокатором `mimalloc`.
