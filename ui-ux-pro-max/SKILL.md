# UI/UX Pro Max — дизайн-интеллект

Локальная база знаний по UI/UX с поисковым движком: 79 стилей (50 активных), 192 продуктовые палитры и профили-рассуждения, 74 шрифтовые пары, 119 UX-правил, 105 иконок, 17 GSAP-пресетов, 25 типов графиков, 22 стека.

Каталог скилла: `scripts/search.py` — поисковый движок; `data/*.csv` — базы данных; `references/quick-reference.md` и `references/pro-rules.md` — справочники (читать по требованию, не грузить каждый раз).

## Когда применять

Задача касается **структуры UI, визуальных решений, паттернов взаимодействия или качества UX**: новые страницы, создание/рефакторинг компонентов, выбор систем цвета/типографики/отступов/раскладки, ревью UI на доступность и консистентность, навигация, анимации, адаптивность, воспринимаемое качество.

Пропускать для чистого бэкенда, API/БД, не-визуальной производительности, инфраструктуры и скриптов — если только это не меняет то, как продукт **выглядит, ощущается, движется или с чем взаимодействует**.

## Запуск поискового скрипта

Скрипт лежит внутри каталога скилла (далее `<SKILL_DIR>` — абсолютный путь каталога, OpenCode сообщает его при загрузке скилла). Вызывать по полному пути, не рассчитывая на рабочую директорию:

```powershell
py "<SKILL_DIR>\scripts\search.py" "<запрос>" --domain <домен>
```

Если `py` не найден — попробовать `python`, затем `python3`. Нужен Python 3.x; внешних зависимостей нет, сеть скрипт не трогает, ничего не устанавливает. Если Python на машине отсутствует — попросить пользователя установить, самому ничего не ставить.

## Приоритеты правил

| # | Категория | Влияние | Домен | Ключевые проверки | Антипаттерны |
|---|-----------|---------|-------|-------------------|--------------|
| 1 | Доступность | КРИТИЧНО | `ux` | Контраст 4.5:1, alt-текст, навигация с клавиатуры, aria-label | Удалённые focus rings, иконочные кнопки без подписей |
| 2 | Касание и взаимодействия | КРИТИЧНО | `ux` | Зоны от 44×44px, отступы 8px+, индикация загрузки | Только hover, мгновенные смены состояний (0 мс) |
| 3 | Производительность | ВЫСОКО | `ux` | WebP/AVIF, ленивая загрузка, резерв места (CLS < 0.1) | Layout thrashing, прыжки контента |
| 4 | Выбор стиля | ВЫСОКО | `style`, `product` | Соответствие типу продукта, консистентность, SVG-иконки | Смешение стилей, эмодзи вместо иконок |
| 5 | Раскладка и адаптивность | ВЫСОКО | `ux` | Mobile-first брейкпоинты, viewport meta, без гориз. скролла | Горизонтальный скролл, фиксированные px-ширины, запрет зума |
| 6 | Типографика и цвет | СРЕДНЕ | `typography`, `color` | База 16px, межстрочный 1.5, семантические цветовые токены | Текст < 12px, серый на сером, сырые hex в компонентах |
| 7 | Анимация | СРЕДНЕ | `ux`, `gsap` | Тайминги по контексту, движение несёт смысл, пространственная непрерывность | Одна длительность для всех переходов, анимация width/height, нет reduced-motion |
| 8 | Формы и обратная связь | СРЕДНЕ | `ux` | Видимые подписи, ошибка у поля, подсказки, прогрессивный показ | Подписи только в placeholder, ошибки только сверху |
| 9 | Навигация | ВЫСОКО | `ux` | Предсказуемый back, нижнее меню ≤ 5 пунктов, deep links | Перегруженное меню, сломанный back, отсутствие deep links |
| 10 | Графики и данные | НИЗКО | `chart` | Легенды, тултипы, доступные цвета | Смысл передаётся только цветом |

Полный перечень правил каждой категории — `references/quick-reference.md`. Правила полировки мобильных приложений и финальный чеклист — `references/pro-rules.md`.

## Договорённость по запросам

Выбирай минимальный режим поиска:

1. Новый проект/страница или общее визуальное направление → `--design-system`.
2. Точечное опасение или баг компонента → один явный `--domain`.
3. Известный стек реализации → `--stack`; отдельный domain-запрос — только для отдельного дизайн-вопроса.

Запрос строится вокруг **одной главной цели**: 2–5 осмысленных слов плюс одно ограничение (продукт, платформа, взаимодействие). Перед применением результата проверь домен, верхний результат и уместность. Пустой или нерелевантный ответ → **один** ретрай с более узкой формулировкой или явным доменом/стеком; если снова пусто — так и сказать: проверенного совпадения нет, общие рекомендации помечать как фолбек. Несохранять непроверенный вывод.

Для доступности — один наблюдаемый исход за запрос: сначала семантика (`"error summary validation" --domain ux`), затем компонент (`"icon button accessible label" --domain icons`), и только потом стек. Для багов текста/компактных компонентов: сначала UX-исход (`"badge chip label wraps"`), затем стек (`"chip badge overflow nowrap" --stack html-tailwind`).

Скрипт даёт рекомендации, а не инструкции: они не отменяют правила пользователя и репозитория. Не передавать приватные данные проекта в запросы.

## Шаг 1. Анализ требований

Из запроса пользователя извлечь:
- **Тип продукта**: SaaS, e-commerce, портфолио, дашборд, развлечение, инструмент…
- **Аудитория и контекст**: возраст, сценарий (в пути, работа, досуг)
- **Ключевые слова стиля**: игривый, минималистичный, тёмная тема, контент-фёрст…
- **Стек**: определить по проекту — `package.json` (react/next/vue/svelte/nuxt/@angular), `pubspec.yaml` (Flutter), `composer.json` (Laravel), маркеры React Native. Если стек не определяется и гайды по стеку важны — спросить. **Не предполагать стек.**

## Шаг 2. Генерация дизайн-системы (обязательна для новых страниц/проектов)

```powershell
py "<SKILL_DIR>\scripts\search.py" "<тип_продукта> <индустрия> <ключевые_слова>" --design-system -p "Имя проекта"
```

Пример:
```powershell
py "<SKILL_DIR>\scripts\search.py" "beauty spa wellness service" --design-system -p "Serenity Spa"
```

Возвращает: паттерн посадочной страницы, стиль, палитру, типографику, эффекты и антипаттерны.

## Шаг 2b. Сохранение (Master + переопределения страниц)

```powershell
py "<SKILL_DIR>\scripts\search.py" "<запрос>" --design-system --persist -p "Имя проекта" --output-dir "<корень проекта>"
```

Создаёт `design-system/<слаг>/MASTER.md` (глобальный источник истины) и `design-system/<слаг>/pages/<страница>.md` (только отклонения от Master; опционально `--page "имя`").

Правила:
- Всегда передавать `--output-dir` с корнем проекта — иначе файлы уйдут относительно случайной рабочей директории.
- Если `MASTER.md` уже существует — прочитать его и **не** перезаписывать; `--force` только по явной команде пользователя.
- При сборке конкретной страницы: 1) прочитать `pages/<имя>.md` — если есть, его правила главнее; 2) иначе — Master.

## Шаг 2c. Диалеры (опционально)

```powershell
py "<SKILL_DIR>\scripts\search.py" "<запрос>" --design-system --variance 6 --motion 4 --density 6
```

| Диалер | Низко (1–3) | Средне (4–7) | Высоко (8–10) |
|--------|-------------|--------------|----------------|
| `--variance` | центрированный, минимализм | сбалансированный, современный | смелый, асимметричный (бенто, брутализм) |
| `--motion` | тонкие микровзаимодействия | стандартный scroll/stagger | сложная хореография (pin, Flip, SplitText) |
| `--density` | просторный (24–96px) | стандарт (16–64px) | плотный дашборд (8–32px) |

Не заданные диалеры не меняют вывод. `--density` переопределяет таблицу `--space-*` переменных.

## Шаг 3. Уточняющие поиски по доменам

| Нужна информация | Домен | Пример |
|------------------|-------|--------|
| Паттерны по типу продукта | `product` | `"entertainment social" --domain product` |
| Стили | `style` | `"glassmorphism dark" --domain style` |
| Палитры | `color` | `"fintech trust blue" --domain color` |
| Шрифтовые пары | `typography` | `"playful modern" --domain typography` |
| Отдельные Google Fonts | `google-fonts` | `"sans serif popular variable" --domain google-fonts` |
| Типы графиков | `chart` | `"real-time dashboard" --domain chart` |
| UX-правила | `ux` | `"error summary validation" --domain ux` |
| Структура лендинга | `landing` | `"hero social-proof" --domain landing` |
| Иконки | `icons` | `"decorative icon aria hidden" --domain icons` |
| GSAP-пресеты | `gsap` | `"scroll reveal stagger" --domain gsap` |
| React/Next.js производительность | `react` | `"rerender memo list" --domain react` |
| Мобильные/нативные гайды | `web` | `"accessibilityLabel touch safe-areas" --domain web` |

Домен определяется автоматически, но автодетект путается на пересекающихся терминах — при сомнении указывать `--domain` явно.

## Шаг 4. Гайды по стеку

```powershell
py "<SKILL_DIR>\scripts\search.py" "<ключевое слово>" --stack <стек>
```

Стеки: `react`, `nextjs`, `vue`, `svelte`, `astro`, `nuxtjs`, `nuxt-ui`, `angular`, `laravel`, `swiftui`, `react-native`, `flutter`, `jetpack-compose`, `html-tailwind`, `shadcn`, `threejs`, `javafx`, `wpf`, `winui`, `avalonia`, `uno`, `uwp`.

## Если поиск вернул 0 результатов

Не выдумывать:
1. Один ретрай с более узким запросом или явным `--domain`/`--stack`.
2. Если пусто — опираться на таблицу приоритетов и явно пометить: «данных по Х нет, использую общие дефолты».
3. Не выдавать пустой поиск как успешный результат.

## Форматы вывода

`--design-system`: `-f ascii` (по умолчанию), `-f markdown` (документация), `--json` (машинный).

## Перед сдачей UI

Прочитать `references/pro-rules.md` и пройтись по финальному чеклисту: дисциплина иконок, обратная связь взаимодействий, контраст light/dark, safe-area, доступность. Для нативных приложений (iOS/Android/React Native/Flutter) — его мобильный чеклист.
