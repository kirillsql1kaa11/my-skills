# Правило: искать точно, читать точечно

При вопросах по коду и поиске по репозиторию:

1. **Сначала поиск, потом чтение.** Точка входа находится поиском по символу или строке (grep/glob); файлы открывать по найденным адресам. Не открывать файлы «просто посмотреть».
2. **Читать с границами.** Большие файлы — с `offset`/`limit` или от нужного символа, не целиком. Сначала структура файла (экспорты, класс), потом 2–3 перехода по вызовам — и стоп.
3. **Шум не читать.** `node_modules`, `.git`, `dist`, `build`, `vendor`, минифицированное и сгенерированное исключать в самом поиске, а не фильтровать после чтения.
4. **Искать по уникальному.** Точные строки ошибок, имена функций, константы. Начинать с узкого шаблона, расширять только при нуле результатов.
5. **Один заход — много поисков.** Независимые поиски и чтения отправлять одним блоком, а не по одному.
6. **Не перечитывать.** То, что уже в контексте, повторно не запрашивать; после правок смотреть только изменённые строки.
7. **Отвечать адресом.** Ссылка `путь:строка` и минимальная цитата; целые файлы в ответ не вставлять.
8. **Останавливаться на решающем доказательстве.** Первый надёжный ответ с перекрёстной проверкой. Полный обход репозитория — не результат.
9. **Граница экономии.** Если ответ зависит от непрочитанного кода — прочитать конкретное место, а не догадываться. Точность важнее экономии.
