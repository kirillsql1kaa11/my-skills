# Правило: формы без боли

При создании или правке любой формы — регистрация, поиск, оплата, настройки:

1. **Ярлык важнее подсказки.** У каждого поля настоящий `<label>`, связанный с полем; placeholder — только пример (`ivan@example.com`), не замена ярлыку.
2. **Валидация не мешает печатать.** Проверка на `blur` и при отправке, не на каждый символ; символы во время ввода не вычищать. После первой ошибки поле может проверяться на `input` — чтобы ошибка исчезала сама.
3. **Ошибка — человеческая и рядом.** «Введите дату в формате ДД.ММ.ГГГГ», а не «Ошибка валидации»; текст у самого поля, не в углу страницы. Несколько ошибок — сводка и фокус на первом неверном поле.
4. **Ввод не теряется.** Ошибка отправки форму не сбрасывает; поля не очищать и не отключать на время отправки — блокируется только кнопка. Черновик переживает перезагрузку там, где это уместно.
5. **Честные состояния.** Кнопка: обычная → «Отправляем…» (disabled) → успех/ошибка. Двойная отправка исключена и на клиенте, и на сервере; успех подтверждается явно.
6. **Доступность по умолчанию.** Ошибку видно глазами и слышно скринридером: `aria-invalid`, `aria-describedby` с текстом ошибки, объявление через `role="alert"`/`aria-live`; видимый фокус, осмысленный порядок табуляции, Enter отправляет, Esc закрывает.
7. **Поля просят то, что просят.** Корректные `type`, `inputmode`, `autocomplete` (`email`, `tel`, `one-time-code`, `new-password`, `current-password`). Вставку из буфера не запрещать — включая код из письма.
8. **Пароли без самодурства.** Длина важнее правил состава; максимум не занижать (не меньше 64 символов); пробелы и менеджеры паролей разрешены; есть показать/скрыть; пароль не обрезать по краям.
9. **Ошибки сервера — по полям.** Ответ API раскладывать по конкретным полям; непривязываемое — общий блок с честным текстом и повтором. Данные при этом на месте.

Работает вместе с `ui-ux-pro-max` (паттерны и стиль) и `responsive-basics` (адаптивность).
