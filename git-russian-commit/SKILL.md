# Регламент подготовки коммитов (git-russian-commit)

Данный навык устанавливает стандарты и последовательность действий при создании коммитов в системе контроля версий Git.

## Главные правила

1. Язык: Все сообщения коммитов пишутся строго на русском языке.
2. Никаких эмодзи: Использование эмодзи, иконок и декоративных спецсимволов полностью запрещено.
3. Осмысленность: Сообщение обязано четко объяснять суть внесенных изменений. Запрещены общие формулировки: «правки», «фикс», «обновление», «wip», «test».
4. Атомарность: Один коммит должен решать одну логическую задачу. Не смешивать рефакторинг, исправление ошибок и форматирование в одну фиксацию.

---

## Порядок выполнения коммита

### Шаг 1. Анализ текущего состояния

Перед добавлением файлов в индекс необходимо проверить измененные и неотслеживаемые файлы:
```powershell
git status
```

### Шаг 2. Проверка содержимого изменений

Убедиться, что в изменения не попали временные файлы, артефакты сборки, секреты или не относящиеся к задаче правки:
```powershell
git diff
```

### Шаг 3. Индексация файлов

Индексировать только файлы, относящиеся к текущей задаче:
```powershell
git add <путь-к-файлу-1> <путь-к-файлу-2>
```

Проверить подготовленные к коммиту изменения:
```powershell
git diff --staged
```

### Шаг 4. Формирование сообщения и коммит

Сообщение должно начинаться с глагола в неопределенной форме (инфинитиве) с заглавной буквы:
- Добавить...
- Исправить...
- Реализовать...
- Удалить...
- Оптимизировать...
- Рефакторить...

Пример выполнения:
```powershell
git commit -m "Исправить утечку дескрипторов при закрытии соединения в MiniRaycast"
```

## Многострочные коммиты для крупных изменений

Если изменение требует подробного контекста, используется заголовок (до 72 символов) и тело сообщения через пустую строку:

```powershell
git commit -m "Реализовать пакетную обработку аудиопотоков" -m "Перенести транскодирование в отдельный рабочий поток для устранения блокировок пользовательского интерфейса при скачивании длинных треков."
```

## Примеры сообщений

### Недопустимо
- `update`
- `fix bug`
- `правки`
- `исправления по ревью`
- `чуть-чуть подправил логику`

### Корректно
- `Добавить проверку энтропии для фильтрации ложных срабатываний в Git-Secret-Hunter`
- `Исправить падение приложения при открытии поврежденных RAR-архивов`
- `Оптимизировать загрузку списка номенклатуры в модуле складского учета`
- `Удалить устаревшие неиспользуемые DTO модели из проекта`
