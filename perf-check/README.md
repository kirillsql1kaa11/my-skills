# perf-check

Оптимизация только через измерения: сначала замер-база, затем одно целевое изменение, затем повторный замер с цифрами «было → стало».

**Инструмент:** opencode
**Триггер:** автоматически при запросах «медленно», «тормозит», «оптимизируй», «сделай быстрее»

## Что делает

- Заставляет уточнить, что именно медленно и насколько, до любых правок
- Подбирает инструмент замера под стек:
  - Node/JS: `node --cpu-prof`, `console.time`, `hyperfine`, `autocannon`
  - Python: `timeit`, `cProfile`, `py-spy`
  - .NET: BenchmarkDotNet, `dotnet-trace`
  - Go: `go test -bench`, `pprof`
  - БД: `EXPLAIN ANALYZE`, slow query log
- Требует зафиксировать цифру «до» — без неё оптимизация не начинается
- Строит гипотезу узкого места из данных замера, а не из интуиции
- Вносит одно целевое изменение за раз, а не пачку правок
- Показывает измеренный результат; прогнозы «должно стать быстрее» не выдаёт
- Честно говорит «не стоит оптимизации», если выигрыш меньше ~10%

## Установка

```powershell
Copy-Item -Recurse perf-check "$env:USERPROFILE\.config\opencode\skills\"
```
