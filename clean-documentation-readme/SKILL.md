# Регламент оформления README (clean-documentation-readme)

Данный навык устанавливает стандарты структуры, полноты и ясности файлов `README.md` для программных репозиториев.

## Основные принципы

1. Документация должна быть самодостаточной: новый разработчик должен развернуть и запустить проект по инструкциям без устных пояснений.
2. Все приведенные команды обязаны быть рабочими и скопированными из актуального пайплайна сборки.
3. В файле не должно быть неактуальных ссылок, заготовок и заглушек.
4. Оформление выполняется в строгом нейтральном стиле без использования эмодзи.

---

## Стандартная структура `README.md`

### 1. Заголовок и описание
- Название проекта первым уровнем заголовка (`# Project Name`).
- Одно или два предложения, исчерпывающе объясняющие практическое назначение и решаемую задачу.

### 2. Ключевые возможности (Features)
- Маркированный список основных функций и архитектурных особенностей системы.

### 3. Системные требования (Prerequisites)
- Список необходимых рантаймов, компиляторов и внешних утилит с указанием минимальных поддерживаемых версий (например: Node.js 20+, Rust 1.80+, .NET 9 SDK, Docker 26+).

### 4. Быстрый старт (Quick Start)
- Минимальный список команд для клонирования, установки зависимостей и первого запуска локально:

```powershell
git clone https://github.com/org/project.git
cd project
npm install
npm run dev
```

### 5. Конфигурация и переменные окружения
- Таблица используемых параметров конфигурации с описанием, типами и значениями по умолчанию:

| Переменная | Описание | Обязательная | Значение по умолчанию |
| :--- | :--- | :--- | :--- |
| `DATABASE_URL` | Строка подключения к базе данных | Да | `sqlite://local.db` |
| `SERVER_PORT` | Порт прослушивания HTTP-сервера | Нет | `8080` |
| `LOG_LEVEL` | Уровень детализации логирования | Нет | `info` |

### 6. Сборка, тестирование и линтинг
- Точные команды для проверки проекта перед отправкой изменений:

```powershell
cargo test
cargo clippy --all-targets -- -D warnings
cargo build --release
```

### 7. Архитектура и структура каталогов
- Краткая карта ключевых директорий репозитория:

```text
├── src/
│   ├── api/          # Маршрутизаторы и обработчики HTTP-запросов
│   ├── core/         # Чистая доменная бизнес-логика
│   ├── storage/      # Работа с базами данных и внешними хранилищами
│   └── main.rs       # Точка входа в приложение
├── tests/            # Интеграционные и сквозные тесты
└── Cargo.toml        # Зависимости и конфигурация пакета
```

### 8. Лицензия
- Указание типа лицензии со ссылкой на корневой файл `LICENSE` (например: Проект распространяется под условиями лицензии [MIT](LICENSE)).

## Чек-лист проверки качества README

- Все команды протестированы на чистой системе или в контейнере.
- В блоках кода отсутствуют комментарии.
- В тексте отсутствуют эмодзи и иконки.
- Описаны все используемые переменные окружения.
- Указаны конкретные версии зависимостей и инструментов.
